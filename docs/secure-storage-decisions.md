# 구현 판단과 검토 결과

원래 합의한 JS 범위에서 판단한 내용입니다. 운영 배포는 포함하지 않습니다.

1. **구버전 writer 차단:** 기존 config store를 이름 변경하고 JWT·세션 설정은 유지합니다. 기존 이름을 남기면 구버전 코드가 평문을 다시 쓸 수 있습니다. 대신 열려 있는 구버전 탭의 SDK 작업은 실패할 수 있어 새 SDK로 로드해야 합니다.
2. **설정 선조회:** 현재 워커 경로를 알아야 이관 여부를 결정할 수 있으므로 공개 SDK 설정을 저장소 이관 전에 조회합니다. 같은 응답을 Session에 전달하여 추가 요청은 만들지 않습니다. 설정 조회 실패 시 저장소 이관도 시작하지 않습니다.
3. **원본 정리 실패:** 검증 후 평문 삭제와 ready 전환을 한 트랜잭션으로 수행합니다. 실패하면 초기화를 false로 종료하고 pending을 보존합니다. 가용성보다 불완전한 전환 방지를 우선합니다. 호환 워커도 암호문을 검증하고 같은 확정 절차로 복구할 수 있습니다. 저장소 오류 자체가 지속되면 페이지와 워커 모두 식별자 사용을 중단합니다.
4. **알 수 없는 기존 워커:** 과거 Notifly 워커 기록과 경로가 다른 푸시 구독이 함께 있으면 capability를 확인합니다. 응답 없는 모호한 등록 때문에 이관이 보류될 수 있습니다. 이름에 notifly가 들어 있다는 이유만으로 무관한 워커를 차단하지 않습니다.
5. **사용자 전환 경쟁:** 전환을 결정한 스냅샷으로 CAS하고 성공한 스냅샷을 이벤트에 전달합니다. 동시 전환 충돌 시 다른 탭의 최신 ID를 덮어쓰지 않습니다. 초기 복원과 서버 매핑 보정의 단일 충돌은 제한적으로 재판단합니다. 사용자 상태·속성·SSE·지연 팝업은 revision을 검증합니다.
6. **진단 전송 범위:** 성능 계측은 로컬 Performance API에 남기고 기존 RUM·CloudWatch 연결 방법을 문서화합니다. 새 서버 진단 이벤트를 임의로 보내지 않습니다. 운영 대시보드 연결과 실제 부하 관찰은 릴리스 단계에 남습니다.
7. **검증 구성:** 이관 실패 테스트는 별도 mock 전용 파일 대신 fake-indexeddb 트랜잭션 테스트에 함께 둡니다. 실제 Chrome/Firefox/WebKit과 프로세스 재시작을 별도로 검증합니다. 실제 Safari/iOS 기기 및 APNs/FCM·OS 알림 UI는 별도 검증이 필요합니다.
8. **기존 워커 해시:** 페이지 UUID v5와 다른 기존 워커 자체 해시는 이번 작업에서 변경하지 않았습니다. 이 차이는 유지되므로 별도 호환성 검토가 필요합니다.

독립 리뷰에서 확인한 사용자 귀속·워커 탐지·지연 팝업·진행 중 upgrade 타임아웃·초기화 충돌·pending 워커 복구를 실패하는 회귀 테스트로 재현한 뒤 수정했습니다. 검증용 로컬 KMP Core도 고정된 서브모듈에서 2.22.0으로 다시 빌드했으며 baseline fixture는 실제 Core 콘텐츠 지문으로 캐시를 구분합니다.

**보류한 작은 개선:** 다른 탭의 사용자 변경 직후 여러 이벤트가 동시에 들어오면 같은 사용자의 refresh가 중복 대기할 수 있습니다. 잘못된 사용자 반영은 차단하지만 동일 조회 Promise 공유를 통한 요청 수 최적화는 포함하지 않았습니다.
